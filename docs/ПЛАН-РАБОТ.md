# ЭТАП 1. Сломанное — чинить первым

### 🔴 1.1. Чат раскрыт всегда и закрывает экран

**Что видит гость.** На телефоне окно чата занимает весь экран сразу при
загрузке **любой** страницы, до всякого нажатия. Сайта не видно. И окно
пустое — приветствие добавляется только при нажатии, которого не было.

**Причина (найдена, не догадка).** Атрибут `hidden` не работает, потому что
наш CSS задаёт окну `display: flex`, а правила-противовеса в стилях нет.
Проверено: поиск `[hidden]` по всему собранному CSS не находит ничего.

**Решение.** Одна строка в `global.css`, слой `reset`:
`[hidden] { display: none !important }`. `!important` обязателен — вес
селектора `[hidden]` (0-1-0) проигрывает `.chat-panel[data-astro-cid-…]` (0-2-0).

Правило чинит `hidden` разом для всего сайта, а не только для чата —
это устранение причины, а не заплатка.

**❓ Вопрос владельцу (без ответа с 26.07):** после починки чат будет
открываться по нажатию. На телефоне сейчас задумано **во весь экран**.
Так удобно — или сделать окно поменьше, чтобы за ним был виден сайт?
Оба варианта одинаково просты.

### 🔴 1.2. Адреса страниц: одна настройка вместо трёх правок

**Проблема.** Каждая страница сообщает Google неверный собственный адрес:
canonical говорит `/tours.html`, а карта сайта и все ссылки — `/tours`.
Ради сохранения 14 лет истории адреса берегли 1:1 с Wix, и этот дефект
бьёт ровно в эту цель.

**Решение — проверено настоящей сборкой обоими агентами независимо.**
В `astro.config.mjs` заменить `build: { format: 'file' }` на
`build: { format: 'directory' }`.

Одна строка закрывает **три** проблемы:

| Было | Стало |
|---|---|
| canonical → `/tours.html` | canonical → `/tours` ✅ |
| главная объявляла себя `/index.html` | главная → `santorinigid.com` ✅ |
| файл `vip-service.html` и папка `vip-service/` конфликтуют | конфликта нет ✅ |

**Что проверено на собранной копии** (проект при этом не менялся):
все 10 адресов совпадают с картой сайта символ в символ; подсветка активного
пункта меню работает; 417 ссылок, 0 битых; 11 страниц, сборка 1.5 сек
без предупреждений; `404.html` остаётся в корне, как требует GitHub Pages.

**Побочная выгода.** Проверять что-либо после публикации больше не нужно —
конфликт `/vip-service` исчезает как явление, а не «вероятно разрешится».

**На заметку на будущее.** `format: 'directory'` и `trailingSlash: 'never'`
связаны: адреса физически становятся папками, но косая черта в ссылках
не появляется. Проверено — работает верно. Менять `trailingSlash` без
перепроверки нельзя.

### 🔴 1.3. Кнопки в тёмной теме почти не читаются

**Что видит гость.** При включённой тёмной теме (каждый второй современный
телефон) главные кнопки — «Выбрать экскурсию», «Отправить», «Оставить
отзыв» — становятся светло-голубыми с белым текстом.

Контраст **1.53 : 1** при норме 4.5 : 1. Затронуто **24 кнопки**.

**Почему незаметно на компьютере.** При наведении мышью кнопка темнеет,
контраст подскакивает до 9.98 : 1 и всё читается. Дефект виден только
в спокойном состоянии — то есть именно на телефоне, где наведения нет.

**Причина.** `--accent` в тёмной теме подменяется на светлый `#a9d8ef`,
а цвет текста `.btn-primary` жёстко записан белым и не меняется
(`global.css:455–458`, переопределения для тёмной темы нет).

**Решение.** Задать цвет текста кнопки для тёмной темы отдельно —
тёмный на светлом фоне. Зелёных кнопок WhatsApp это не касается: у них
свои цвета, 7.33 : 1, всё в порядке.

**❓ Вопрос владельцу:** чинить цвет — или отключить тёмную тему совсем?
Переключателя на сайте всё равно нет, она включается только по настройке
телефона.

### 🔴 1.4. Главная картинка грузится с задержкой на 7 страницах из 8

**Что теряем.** Google измеряет скорость сайта по времени появления самой
крупной картинки экрана. На главной приоритет задан правильно, а на
экскурсиях, контактах, о Санторини, VIP-услугах, яхтах, вертолётах и отелях
стоит «грузить потом» (`lazy`).

**Причина.** `Hero.astro` ставит приоритет по параметру `priority`,
а передан он только в `index.astro`.

**Решение.** Картинка в шапке видна сразу **по определению** — приоритет
должен стоять по умолчанию, а не по отдельной просьбе. Меняется значение
по умолчанию в компоненте, а не семь страниц по очереди.

# ЭТАП 2. Правда и обязательства — до публикации

### 🟠 2.1. Стаж, вписанный цифрами в 7 местах

Механизм автоматического пересчёта сделан правильно (`site.ts`), но в обход
него цифры вписаны руками: `ChatWidget.astro:107,161`, `Footer.astro:27`,
`BaseLayout.astro:41`, `about.astro:23,38`, `tours.astro:16`.

**1 января 2027 года все семь мест начнут врать.** В подвале — на каждой
из 11 страниц. Сюда же `site.ts:126`: `'© 2026'`.

**Решение.** Подставлять готовые строки `ISLAND_YEARS_TEXT` и
`GUIDE_YEARS_TEXT`, год копирайта считать при сборке.

---

### 🟠 2.2. Форма отзыва обещает то, чего не сделает

Форма пишет гостю «отзыв и фотографии появятся на сайте» и просит согласие
на публикацию фото. Цепочка рвётся дважды: Worker не записывает поле
`photos` в файл (`review-worker.js:331–343`), а карточка отзыва не умеет
их показывать. Фотографии не появятся никогда.

**❓ Вопрос владельцу:** доделать показ фотографий — или убрать обещание
из текста формы? Первое честнее, второе быстрее.

---

### 🟠 2.3. Форма контактов не проверяет email

У формы стоит `novalidate`, а в коде проверяется только имя. При пустом
email заявка уйдёт в WhatsApp без обратного адреса.

**Решение.** Та же строка, что уже правильно работает в форме отзыва:
`if (!form.reportValidity()) return`.

---

### 🟠 2.4. Сообщения форм плохо читаются

Контраст на фоне формы (норма 4.5 : 1):

| Цвет | Светлая тема | Тёмная тема |
|---|---|---|
| зелёный «отправлено» | **3.48 ✗** | **4.15 ✗** |
| красный «ошибка» | 5.44 ✅ | **2.66 ✗** |
| звёздочка «обязательное поле» | **3.74 ✗** | — |

Три промаха из четырёх. Звёздочка — единственный знак обязательных полей.

**Решение.** Завести цвета «успех» и «ошибка» в палитре со значениями
для обеих тем, как сделано для всех остальных цветов сайта.

---

### 🟠 2.5. Файл для ИИ-поисковиков занижает достижения

`llms.txt` дважды сообщает «15 отзывов за 2014–2025». Правда: **22 отзыва
за 2014–2026**, с двух площадок. Файл читают ChatGPT и Claude, когда о
владельце спрашивают.

# ЭТАП 4. Независимость и право — перед публикацией

### 🟠 4.1. Шрифты в проект

Единственная внешняя зависимость сайта — Google Fonts. Если Google
недоступен, сайт теряет типографику; заодно IP каждого гостя уходит в Google.
Локальных файлов шрифтов в проекте нет.

Противоречит главному принципу проекта: «что будет, если сервис исчезнет».

**Решение.** Положить файлы шрифтов в проект. Зависимостей станет ноль,
и заодно закроется утечка IP.

---

### 🟠 4.2. Политика конфиденциальности

Отдельной страницы нет. Сайт собирает имя, email, телефон, фотографии.
Владелец ведёт деятельность в Греции (ЕС) — GDPR применяется напрямую.
Фраза «Ваши данные конфиденциальны» в форме политику не заменяет.

---

### 🟡 4.3. Иконки для установки на телефон

В манифесте заявлено `display: standalone` — «меня можно установить как
приложение». Не сработает: нужны иконки 192×192 и 512×512, их нет.
Service worker при этом **не требуется** [MDN].

# ЭТАП 5. После публикации

### 5.1. Домен и перенаправления

- Купить `santorinigid.com` (Porkbun). **Имя свободно на 27.07.2026,
  занять его может кто угодно.**
- Постраничные перенаправления `santorinivip.com` → `santorinigid.com`.
  В коде их сейчас нет вовсе — отдельная работа.
- «Смена адреса» в Google Search Console.

**Честное предупреждение.** При переезде позиции просядут на недели —
это норма для любого переезда, включая идеально сделанный. Перенаправления
и Search Console сокращают просадку, но не отменяют её.

### 5.2. Безопасность Worker — только перед его включением

Три дыры закрыть до подключения: приём открыт всему интернету
(`Allow-Origin: *`), нет ограничения частоты, фото до 21 МБ за запрос.
Плюс поправить почту в комментарии.

**Что проверено и в порядке:** подписи кнопок в письме (HMAC + защита
от подбора по времени) и экранирование чужого текста сделаны правильно.

### 5.3. Что даёт «топ», а чего сайт дать не может

- **Звёзды в выдаче** — только через Google Business Profile и
  Яндекс.Бизнес. Никакой код это не заменит: Google не показывает звёзды
  для отзывов, которые сайт публикует сам о себе.
- **Координаты в разметке** (`geo`) — вклад в местную выдачу «рядом со мной».
- **❓ Статистика посещений** — её нет вовсе, продвижение идёт вслепую.
  Развилка для владельца: счётчик Google даст цифры, но потребует баннера
  о cookies. Есть варианты без слежки и без баннера.

# Чем новый сайт уже лучше Wix — замеры, не слова

| | Wix (santorinivip.com) | Новый сайт |
|---|---|---|
| Служебный «багаж» платформы | 200–400 КБ на каждой странице, убрать нельзя | нет |
| Файлов JavaScript | библиотеки платформы | **0** |
| Вёрстка (CSS) на страницу | — | **32–39 КБ** |
| Вес страницы | — | 39–146 КБ |
| Разметка для поисковиков | не найдена | **31 блок, все валидны** |
| Отзывы видны поисковикам | нет — грузятся скриптом | **все 22 в готовом HTML** |
| Файл для ИИ-поисковиков | нет | есть |
| Слежка за гостями | платформенная | **ноль трекеров** |
| Плата | ежемесячно | только домен, ~$10/год |

Средний сайт на Wix показывает главную картинку за 6.8 сек на телефоне при
норме Google 2.5 сек — это свойство платформы, а не конкретной страницы.

**Но:** пока не сделан этап 1, это преимущество не проявится. Сломанный чат
и противоречивые адреса съедают весь запас.
